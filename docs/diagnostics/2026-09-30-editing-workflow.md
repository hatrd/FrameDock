# 时间轴编辑与封面导出交互

## 问题与行为

左边界无法拖动有两个原因：旧命中规则要求边界距离严格小于播放指针距离，二者重合时总会选择播放指针；默认纯复制模式又在每次 RangeChanged 中写回前一个关键帧，让自由拖动反复退回旧切点。

现在上方绿色 `[`、橙色 `]` 手柄负责边界，下方白色指针负责播放位置。手柄点击保留鼠标抓取偏移，不会因点击手柄内部而跳动。边界与播放指针重合、截取范围很窄时仍能分别拖动。纯复制只计算预计导出切点，不修改所选边界；取消勾选可精确去头。

时间轴有独立视角：滚轮以鼠标所在时间缩放，Shift+滚轮或右/中键拖动平移，底部总览定位视角；F 放大选段，0 返回全片视图，拖到边缘自动滚动。视角操作不修改截取范围。

键盘流程：定位第一帧 → `[` → 定位终点 → `]` → `R` 试听 → 定位封面 → `C` 锁定 → `Shift+D` 导出片段与封面。Home/End 跳到边界，S 单独导出锁定封面（未锁定时用当前画面），Shift+S 始终截取当前帧。画面和字幕在选封面时保存，队列固定提交时的边界和封面，后续编辑不影响任务。打开新视频清空封面。界面增加缩略图、操作提示、输出目录入口，并将“登录时启动”改为“开机时启动”。

## 播放器同步

拖动时合并尚未发出的寻址请求，最终显示最后一次指定的位置。请求回执只代表已接收命令，加载及寻址现在等待 playback-restart 后再读取实际时间；向后逐帧等待寻址完成，向前逐帧等待实际帧位置变化。启动阶段的时间属性可能尚未就绪，加载后重新发布真实帧位置。time-pos 的读取与通知均使用相对源时间原点的位置，保留主线的非零时间原点修复。

事件含义依据 [mpv 官方命令与事件文档](https://mpv.io/manual/master/#command-interface-mpv-event-playback-restart)。合并保留主线成品范围、源包、音轨与首尾画面验证。

## 验证

- `dotnet run --project FrameDock.Tests -c Release`：28 项通过。真实 WinForms 控件与 mpv/FFmpeg，使用两分钟合成视频检查重合手柄、窄范围、缩放锚点和平移、短媒体、边界设置、复制切点分离、封面锁定、提交后更换封面、实际片段与 PNG、快速寻址、前后逐帧、试听停止、最小窗口全部按钮可见、重新打开清空封面。
- `dotnet run --project tests/TimelineRegression -c Release -- artifacts/timeline-regression .scratch/absent-real-video.mp4`：63 项通过，0 失败，结果在 feature 工作树 `artifacts/timeline-regression/20260930-073839/results.json`。覆盖合成 MP4/MKV、H.264/H.265、B 帧、长 GOP、非零原点、静音、短范围、可变帧率、字幕、复用、错误成品拒绝和取消清理。本次未重跑个人真实视频素材。
- 最小窗口布局已通过 DrawToBitmap 检查；截图保存在 `.scratch/interaction-test/minimum-window.png`。视频预览由独立 mpv 子窗口渲染，不包含在 DrawToBitmap 的黑色视频区域里；实际画面和 PNG 已通过播放器截图及内容比较检查。

交互测试需要可用桌面、mpv 和 FFmpeg，测试期间会短暂打开窗口。源视频不会被覆盖；纯复制仍受关键帧与编码包边界约束。
