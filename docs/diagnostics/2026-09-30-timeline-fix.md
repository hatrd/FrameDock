# FrameDock 时间轴修复与验收

日期：2026-09-30。依据：[原始审计](./2026-09-30-timeline-audit.md)。修改应用代码和回归程序；源视频及用户已有成品未覆盖。

## 时间规则

- `MediaInfo.TimelineOrigin` 保存源容器时间原点 O。界面位置 s 对应源显示时间 O+s。关键帧保留原始 PTS、DTS、整数时间戳及 time_base；不截断负 DTS，也不再减去固定 5 毫秒。
- mpv 以 `--rebase-start-time=no` 运行：读取播放位置时减去 O，定位时加上 O，避免依赖播放器与 ffprobe 各自的默认原点。非零起点的 Matroska 容器时长也换算到该原点；MP4 保留其已有相对时长。
- 零起点纯复制完全省略寻址，保留第一 GOP。
- 中间纯复制先输入端定位到所选关键帧 PTS。部分 MKV 的 FFmpeg 输入寻址会退到前一 GOP；随后用所选关键帧相对于 PTS 的 **实际 DTS** 作为输出包保留边界，并相应调整 `-t` 和输出时间偏移。边界按 FFmpeg 的微秒精度向前取整，避免舍入越过关键帧包。这个边界用于保留解码包，界面仍显示 PTS；它与旧实现的“所有模式统一输出端寻址 + 固定补偿”不同。
- 精确模式按实际解码时间执行 `[start,end)` 的 `trim`，保留可变帧率，并用微秒过滤器/编码器 time_base 防止视频定位舍入到整帧而音频仍按原位置切割。字幕在源时间轴上求值。

FFmpeg 对输入/输出寻址的语义见 [官方文档](https://ffmpeg.org/ffmpeg.html#Main-options)。本次 MKV 现象与 FFmpeg 输入寻址中的 DTS 启发式相符，参见 [官方 ffmpeg_demux.c](https://github.com/FFmpeg/FFmpeg/blob/master/fftools/ffmpeg_demux.c)。mpv 原点选项见 [官方手册](https://mpv.io/manual/master/#playback-control)。命令结果以实际包与画面验证为准，不假定某个参数组合适用于所有格式。

## 成品与判重

`Exporter.VerifyAsync` 同时检查容器、编码、轨道、解码画面与源范围：

1. 纯复制的每个视频包及所选音频包必须是源轨道连续序列，SHA-256 内容一致，PTS/DTS 保持同一平移。首视频包必须是所选关键帧。
2. 所选范围内每个实际画面都必须可解码，且显示时间对应源视频。允许复制在 GOP 末尾保留所需参考帧；额外参考帧仍须对应源包及编码边界。
3. 精确模式的画面数和每帧时间必须与源范围一致；首尾画面缩小到 64×64 灰度后与源画面比对，允许平均像素差不超过 8。纯复制的首尾画面必须完全一致。画入字幕时参考画面也按所选字幕生成。
4. 音频保持同一时间平移；允许源编码包的 priming/pre-roll，首尾覆盖必须符合源包边界。容器时长不能代替视频覆盖。
5. 验证源文件状态未变化。缺少可核对的时间戳、包内容或画面时报告失败。HEVC 开放 GOP 在 MKV 中的负时间前导包可能被容器写成无 PTS：仅在内容哈希对应源起点之前的同一包、换算后的源 PTS 确实为负、所有显示画面完整时接受；首帧和任何所选范围内的显示帧不能缺时间。验证完成后才把临时文件移动到正式路径。

后台完成提示显示核实的源视频首帧、末帧和成品时长。既有片段也使用同一验证器；不合格时 UI 将旧文件保留为 `.invalid-...`、显示保留路径并重新排队。直接调用导出器遇到坏的既有文件会保留文件并明确报错，不接受为成功，也不覆盖它。

## 复现与交付

在项目根目录运行：

```powershell
dotnet build FrameDock/FrameDock.csproj -c Release
dotnet run --project tests/TimelineRegression -c Release
./publish.ps1 -Output artifacts/win-x64-timeline-fix
```

回归程序生成独立素材，通过应用实际导出器/验证器运行：MP4/MKV、H.264/H.265、B 帧、长 GOP、非零原点、无音轨、静音导出、50 毫秒短片段、可变帧率、精确模式首尾与粗寻址、字幕画入及特殊文件名、既有成功产物复用、坏 GOP／错误音轨／错误时间偏移拒绝、取消清理。mpv IPC 检查预览首帧、中间切点与默认暂停；使用无画面输出和无声音模式。

每次运行保存 `artifacts/timeline-regression/<时间>/results.json`，其中有每项检查状态及真实导出的首尾/音视频/帧包数记录。`artifacts/timeline-regression/latest.log` 保存本次执行日志。发布目录包含 `FrameDock.exe`、mpv 和说明文件；这是本地构建包，未替换用户其他安装目录。

最终运行：`artifacts/timeline-regression/20260930-072811/results.json`，**67 项通过，0 项失败**。原审计的 `Verify-ZeroStartClip.ps1` 对新 `real-zero.mp4` 再次返回 0。Release 构建及发布成功；发布包用测试视频和 `--tray` 启动，窗口消息循环响应正常且已加载附带的 mpv，检查后关闭测试进程。启动记录在同目录的 `package-smoke.txt`。

测试环境：.NET SDK 8.0.423，Gyan FFmpeg/ffprobe 9.0 full build。发布脚本的消息已改为 ASCII，修复 Windows PowerShell 5.1 将无 BOM 的中文 UTF-8 字符串读错而无法解析脚本的问题。
